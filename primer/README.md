# Набор для нового репозитория

Четыре файла, которые кладутся в любой новый репозиторий организации. После
них проход CI работает сам, а маркетплейс со сводами уже зарегистрирован —
человеку остаётся одна команда, и та один раз на машину, а не на репозиторий:

```
claude plugin install x10-obshchie@x10company
```

| Отсюда | Куда в новом репозитории | Зачем |
|---|---|---|
| `guard.yml` | `.github/workflows/guard.yml` | зовёт общий проход CI восемью строками |
| `settings.json` | `.claude/settings.json` | регистрирует маркетплейс со сводами (сам плагин — на уровне машины) |
| `gitleaks.toml` | `.gitleaks.toml` | исключения для поиска ключей, свои у каждого проекта |
| `gitignore` | `.gitignore` | без него в первый же коммит уедет `__pycache__` |

Имена без точки в начале — иначе они не видны в списке файлов здесь. При
копировании точку вернуть.

## Одной командой

Из корня нового репозитория. Windows:

```powershell
irm https://raw.githubusercontent.com/x10company/ci-guard/main/primer/postavit.ps1 | iex
```

Мак и линукс:

```bash
curl -sSL https://raw.githubusercontent.com/x10company/ci-guard/main/primer/postavit.sh | bash
```

Скачает и разложит все четыре файла. Существующие не трогает — сообщит и
пропустит. Вне репозитория откажется работать. Предупредит, если ветка не
`main`: `guard.yml` запускается на `main`, и на `master` он не запустится ни
разу — на этом уже обожглись в `ApiX10`.

Скрипты — близнецы. Правишь один, правь второй.

## Или руками

```bash
mkdir -p .github/workflows .claude
cp primer/guard.yml       .github/workflows/guard.yml
cp primer/settings.json   .claude/settings.json
cp primer/gitleaks.toml   .gitleaks.toml
cp primer/gitignore       .gitignore
```

## Почему `.gitignore` в этом списке, а не «само собой»

Первый пуш этого самого репозитория **отклонила защита GitHub от секретов**.
Причина: `git add -A` в новом репозитории без `.gitignore` утащил
`tools/__pycache__/check-secrets.cpython-310.pyc`.

Тонкость: в исходнике пробы намеренно склеены из кусков, чтобы сторож не
ругался на собственный текст. Но компилятор складывает константы, и в `.pyc`
они лежат целиком. Защита от текстового поиска не работает против
скомпилированного.

## Почему плагин здесь не включается

Соблазн был: дописать в `settings.json` ключ `enabledPlugins`, и тогда
открывший репозиторий получал бы своды вообще без команд. Так и было сделано
сначала. **Это оказалось ошибкой.**

`enabledPlugins` в настройках проекта заводит **вторую установку** плагина,
замороженную на той версии, что лежала в кэше в момент раскладки.
`claude plugin update` двигает только уровень пользователя — он так и пишет,
«at user scope», — а проектную копию не трогает никогда.

Проверено 04.09.2026 на машине, где этот набор и писали:

```
x10-obshchie@x10company  1.2.0  scope=user
x10-obshchie@x10company  1.0.0  scope=project   c:\Cursor Projects
x10-obshchie@x10company  1.1.0  scope=project   C:\Cursor Projects
```

Три копии трёх разных версий, и две последние — **один и тот же каталог,
записанный с разным регистром буквы диска**. Какая из них действует, снаружи
не видно. Ровно то расхождение, ради устранения которого своды и вынесли в
плагин.

Поэтому в наборе остаётся только `extraKnownMarketplaces`: он ничего не
фиксирует по версии и лишь избавляет от необходимости помнить адрес.
