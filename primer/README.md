# Набор для нового репозитория

Четыре файла, которые кладутся в любой новый репозиторий организации. После
них человеку, который его откроет, **не нужно набирать ничего**: своды правил
подхватятся сами, а коммиты будут проверяться.

| Отсюда | Куда в новом репозитории | Зачем |
|---|---|---|
| `guard.yml` | `.github/workflows/guard.yml` | зовёт общий проход CI восемью строками |
| `settings.json` | `.claude/settings.json` | подключает своды правил при открытии репозитория |
| `gitleaks.toml` | `.gitleaks.toml` | исключения для поиска ключей, свои у каждого проекта |
| `gitignore` | `.gitignore` | без него в первый же коммит уедет `__pycache__` |

Имена без точки в начале — иначе они не видны в списке файлов здесь. При
копировании точку вернуть.

## Порядок

```bash
mkdir -p .github/workflows .claude
cp primer/guard.yml       .github/workflows/guard.yml
cp primer/settings.json   .claude/settings.json
cp primer/gitleaks.toml   .gitleaks.toml
cp primer/gitignore       .gitignore
```

## Почему `.gitignore` в этом списке, а не «само собой»

Первый пуш этого самого репозитория **отклонила защита GitHub от секретов**.
Причина: `git add -A` в новом репозитории без `.gitignore` утащил
`tools/__pycache__/check-secrets.cpython-310.pyc`.

Тонкость: в исходнике пробы намеренно склеены из кусков, чтобы сторож не
ругался на собственный текст. Но компилятор складывает константы, и в `.pyc`
они лежат целиком. Защита от текстового поиска не работает против
скомпилированного.
